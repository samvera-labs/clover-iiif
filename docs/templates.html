Templates

Templates

Layouts for the Viewer, each built only from the parts @nulib/clover exports. Pass one as the Viewer's template, or copy its source (packages/clover/src/templates/<name>/) into your app and change it: nothing in a template is private. Composing Layouts has the parts to build with.

import Viewer from "@nulib/clover";
import { Document } from "@nulib/clover/templates";
import "@nulib/clover/styles.css";
import "@nulib/clover/templates.css";
 
<Viewer iiifContent={url} template={Document} />;

The Viewer is a shell: a page ships only the template it passes. Default is the one it draws when given none, loading it on demand, so its styles are in styles.css. The others are in the stylesheet @nulib/clover/templates.css, which a page that uses none of them can leave out. The Viewer passes every prop but template to its template, and every template takes the Clover.Root props: request, canvasId, annotations, onContentStateChange and the rest.

Default

The Viewer's own layout, drawn when it is given no template: Clover 3.x's Viewer, built from 4.x parts. The thumbnail (xl high, at its own shape up to 5rem wide, cropped past that) and the title over the stage; the thumbnail strip under the stage, whose arrows are Previous and Next, headed by the titles of the view on the left and the position on the right; and the information panel to the right of all three, the layout's full height, scrolling within when its sections run longer. Downloads (the page's and the Manifest's rendering) are listed in the panel's About.

The panel never stacks. As in 3.x it has its own space beside the stage, 24rem to start, and the bar between them shares the width: drag it, or focus it and use the arrow keys (Home and End for the limits; a double click puts it back). The stage keeps at least 16rem and the panel 14rem, and the width the reader chooses is remembered. With no room for both (about 31rem, a phone), the panel slides over the stage instead, leaving a strip of the page uncovered: a click on the strip, Escape or its close button puts it away. The template measures its own width, so a narrow column of a wide page behaves the same. The panel's toggle is always in the stage's top corner and never fades with the other controls.

import Viewer from "@nulib/clover";
import "@nulib/clover/styles.css";
 
<Viewer iiifContent="https://example.org/manifest.json" />;

Given no template, the Viewer loads Default the first time it draws: one request before the Manifest starts to load, and nothing drawn on the server. Its styles are in styles.css, so it needs no templates.css. To have it up front and drawn on the server, pass it: template={Default}, from @nulib/clover/templates.

PropDefaultWhat it does
headertrueThe thumbnail and title over the stage.

storageKey"clover-template-default"Where the panel's width is remembered; false forgets it.

Size the stage with --clover-content-height (default min(65vh, 40rem)).

To change the layout, copy Default.tsx and Default.css into your app, and import the parts from @nulib/clover where they import ../../parts. They use only what @nulib/clover exports, and the slide hooks in templates/shared/useSlide.ts. The split is Clover.Split, Clover.SplitPane and Clover.SplitHandle, which you can use for any layout of your own.

Document

Reads like a PDF viewer: a toolbar across the top, page thumbnails down the left, and one whole page at a time on a grey ground. The bar between the thumbnails and the page widens or narrows them (8rem to 24rem; drag it, or use the arrow keys on it), and the width is remembered. A document of one page has no thumbnails, bar or toggle for them: the page takes the whole width. You never see part of the next page. Scrolling turns the page, one gesture to one page however long a trackpad's momentum runs, and PageUp and PageDown do the same. A scroll short of a turn shows how near it is: the page leans the way it is scrolled and a chevron rises in from the edge the next page comes from, springing back when let go. At the first or last page the wheel scrolls the document on past the viewer. The information panel, from the panel toggle, sits to the right of the page in its own pane where there is room for both, with a bar between them to share the width (remembered as the thumbnails' is). Where there is not (a phone), it slides out over the page instead and takes focus; its close button or Escape puts it away and hands focus back to the toggle.

import Viewer from "@nulib/clover";
import { Document } from "@nulib/clover/templates";
import "@nulib/clover/styles.css";
import "@nulib/clover/templates.css";
 
<Viewer iiifContent="https://example.org/manifest.json" template={Document} />;

Size it with --clover-template-document-height (default min(85vh, 56rem)). Below 40rem the thumbnails cover the page while open, and choosing one puts them away.

A page is a view: a paged Manifest turns a spread at a time, as the pager does. Pinch and Ctrl-wheel still zoom into a page; the plain wheel always turns it.

To change the layout, copy Document.tsx, usePaging.ts and Document.css into your app. They use only what @nulib/clover exports.

Gallery

A grid of a Manifest's views (a spread is one cell) that opens one in a lightbox: its label and position, the stage to pan and zoom, and the pager to move on. The lightbox is a native <dialog>: focus stays inside it, Escape or a press outside closes it, and focus returns to the cell.

import Viewer from "@nulib/clover";
import { Gallery } from "@nulib/clover/templates";
import "@nulib/clover/styles.css";
import "@nulib/clover/templates.css";
 
<Viewer
  iiifContent="https://example.org/manifest.json"
  template={Gallery}
  size="12rem"
/>;
PropDefaultWhat it does
size10remA grid cell's width (sets --clover-items-size).

To change the layout, copy Gallery.tsx, Gallery.css and ../shared/Lightbox.tsx into your app. They use only what @nulib/clover exports.

Text

A Manifest read as text, as Clover 3.x's Scroll reads it: one article per Canvas, its image beside its annotations (transcriptions, translations, comments) in a column per language. A search narrows the pages to those whose text matches; pressing an image opens it in a lightbox to pan and zoom.

import Viewer from "@nulib/clover";
import { Text } from "@nulib/clover/templates";
import "@nulib/clover/styles.css";
import "@nulib/clover/templates.css";
 
<Viewer iiifContent="https://example.org/manifest.json" template={Text} />;
PropDefaultWhat it does
searchtrueThe search field in the sticky header.
…Every Clover.Root prop except annotationPages.

Every Canvas's annotation pages are fetched at once (annotationPages="all"), since they are all on the page. Markdown bodies (text/markdown) are read as Markdown; right-to-left languages run right to left.

To change the layout, copy Text.tsx, Text.css and ../shared/Lightbox.tsx into your app. They use only what @nulib/clover exports.
