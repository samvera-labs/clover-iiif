# Canvas

<Callout type="warning">
  **Experimental.** `Canvas` is Clover's own 2D renderer, under development as a
  possible replacement for OpenSeadragon and Vidstack. Its API may change in any
  release. `Image` and the Viewer's default path are unaffected.
</Callout>

A pan and zoom surface for IIIF images, video and sound, drawn with WebGL2 and falling
back to Canvas2D. Everything on a IIIF Canvas shares one camera, so it moves together.

## IIIF Canvases

`Canvas` draws IIIF Canvases: pass one, or the few you want shown together, as
`canvases`. Each Canvas's painting annotations are composed at their targets, and
several Canvases are laid out in reading order by `viewingDirection`.

`Canvas` knows nothing of the Manifest around those Canvases. Deciding what to show —
reading `behavior` to group a Manifest into single pages, spreads or one joined object —
and stepping between views is the host's job, as it is the Viewer's. Each example below
is a small host doing exactly that for a IIIF Cookbook recipe, with its previous / next
below the `Canvas` rather than inside it. The grouping rules it uses are Clover's own
(`groupViews` in `src/lib/iiif-sequence.ts`), the same ones the Viewer follows.

## Video and sound

A time-based Canvas plays in Clover's own transport: play, a seek bar, volume, time and
captions, styled as the Viewer's Player. On its own, a video is fitted to the stage and
stays put. Beside other Canvases, it is placed in the scene like an image and moves with
them. The media code loads only
when a Canvas paints video or sound, so a page of images never downloads it.

### Video drawn into the canvas

By default a video is a real `<video>` element positioned by the camera. The browser
composites it, so picture-in-picture, AirPlay and HDR keep working. With
`options.media.presentation: "texture"`, each frame is drawn into the WebGL canvas
instead, in paint order with the images around it. Frames upload only as the video
decodes them. This needs CORS on the media: without it, that video falls back to
`dom`.

## Features

`Canvas` covers what `Image` does, apart from OpenSeadragon's own configuration:

- **IIIF Image API 3.0, 2.1.1 and 2.0.** Each service is tiled from its `info.json`:
  - from its `tiles` when it lists them
  - from its `sizes` when it is a level 0 tree that lists only sizes
  - from tiles Clover cuts itself when it is level 1 or 2 and lists none

  Requests use each version's canonical spelling, which is all a static level 0 tree
  answers to. A body whose service cannot be reached falls back to its `id`.

- **Deep zoom.** It loads the coarsest level first, then the level that fits the screen,
  nearest the centre first. Tiles that scroll out of view are cancelled. Tiles stay cached
  up to a memory budget.
- **Several images** (`body` or `src` arrays) are laid out side by side at a common
  height, and **`body.region`** (`x,y,w,h` or `pct:x,y,w,h`) shows only that part of an
  image.
- **Annotations** with rectangular targets become hotspots.
- **Controls:** the same cluster as `Image`, including `controlButtons` replacements.
- **Navigator, full screen and rotation.**
- **No CORS needed.** Images served without CORS are still shown: WebGL may not read
  them, so they are placed as real `<img>` elements by the same camera.
- **Video and sound** (`Video` and `Sound` painting bodies, HLS included) play in
  Clover's own transport, with WebVTT captions, a placeholder poster, and an
  accompanying image for sound.

## Interaction

The controls, navigator, a video or sound's transport, and a soft scrim behind them appear
while the pointer moves over the Canvas or focus is anywhere inside it. They fade after
`hideDelay`, or a second after the pointer or keyboard focus leaves, as the Viewer's
Player does. Chrome shown by keyboard focus stays while focus is inside.

| Input                       | Action                                  |
| --------------------------- | --------------------------------------- |
| Drag                        | Pan, with momentum on release           |
| Click                       | Zoom in (<kbd>Shift</kbd>-click: out)   |
| Pinch                       | Zoom about the pinch                    |
| Trackpad pinch              | Zoom about the pointer                  |
| Wheel                       | Scrolls the page, unless `scrollToZoom` |
| Double tap (touch)          | Zoom in                                 |
| Arrow keys                  | Pan (<kbd>Shift</kbd>: further)         |
| <kbd>+</kbd> / <kbd>-</kbd> | Zoom in / out                           |
| <kbd>0</kbd>                | Home, upright                           |
| <kbd>r</kbd> / <kbd>R</kbd> | Rotate 90° clockwise / anticlockwise    |
| Navigator                   | Press or drag to move there             |

A single video or sound Canvas is a player rather than a picture to explore. It is always
fitted to the stage, at the video's own aspect, and does not pan, zoom or rotate. Its
only chrome is the transport at the bottom, which carries full screen; there are no top
controls or scrim. A click on the picture plays and pauses, and
the focused Canvas takes these keys:

| Input                           | Action                     |
| ------------------------------- | -------------------------- |
| <kbd>Space</kbd> / <kbd>k</kbd> | Play / pause               |
| <kbd>j</kbd> / <kbd>l</kbd>     | Back / forward ten seconds |
| <kbd>m</kbd>                    | Mute                       |

## Usage

```jsx
import Canvas from "@samvera/clover-iiif/canvas";

<Canvas
  src="https://iiif.io/api/image/3.0/example/reference/918ecd18c2592080851777620de9bcb5-gottingen"
  isTiledImage
  label="Göttingen market square"
  onReady={(canvas) => canvas.zoomBy(2)}
  onViewportChange={(bounds) => console.log(bounds)}
/>;
```

## Props

| Prop                 | Type                                             | Description                                                       |
| -------------------- | ------------------------------------------------ | ----------------------------------------------------------------- |
| `canvases`           | IIIF Canvas objects                              | One Canvas, or several shown together (a spread).                 |
| `viewingDirection`   | `"left-to-right"` and so on                      | How to lay out several `canvases`.                                |
| `body`               | IIIF painting body, or an array                  | Image resources to draw. Takes precedence over `src`.             |
| `src`                | `string \| string[]`                             | Image URLs, or image service URIs with `isTiledImage`.            |
| `isTiledImage`       | `boolean`                                        | Treat each `src` as an image service (base URI or `info.json`).   |
| `label`              | `InternationalString \| string`                  | Accessible name for the viewport.                                 |
| `instanceId`         | `string`                                         | A new id remounts the renderer.                                   |
| `annotations`        | `{ annotation, targetIndex }[]`                  | Hotspots, as `Image` takes them. Rectangular targets only.        |
| `onAnnotationActive` | `(id: string \| null) => void`                   | The hovered or focused hotspot.                                   |
| `navigator`          | `boolean`                                        | Show the overview. Default `true`.                                |
| `controls`           | `boolean \| { zoom, fullPage, rotation, reset }` | Which controls to show. Default all.                              |
| `controlButtons`     | `ControlButtons`                                 | Replace any control, as the Viewer's `controlButtons`.            |
| `options`            | `CloverCanvasOptions`                            | See below.                                                        |
| `onReady`            | `(handle: CanvasHandle) => void`                 | Called once the first images are laid out and fitted.             |
| `onViewportChange`   | `(bounds: Rect) => void`                         | The visible region, in image coordinates, at most once per frame. |
| `onMediaElement`     | `(element: HTMLVideoElement \| null) => void`    | A time-based Canvas's media element, for a host's own transcript. |
| `onEnded`            | `() => void`                                     | Playback reached the end: a host's cue to advance.                |

### `options`

| Option               | Default  | Description                                                                            |
| -------------------- | -------- | -------------------------------------------------------------------------------------- |
| `backend`            | `"auto"` | `"auto"`, `"webgl2"` or `"canvas2d"`.                                                  |
| `gestures`           |          | `clickToZoom`, `dblClickToZoom`, `pinchToZoom`, `scrollToZoom` (`false`).              |
| `maxZoomPixelRatio`  | `1.1`    | Largest zoom, in CSS pixels per image pixel.                                           |
| `minZoomImageRatio`  | `0.9`    | Smallest zoom, as a fraction of the home zoom.                                         |
| `animationTime`      | `0.09`   | Easing time constant in seconds. `0` under reduced motion.                             |
| `hideDelay`          | `2000`   | Milliseconds the controls and navigator stay after the pointer stops, as the Player's. |
| `withCredentials`    | `false`  | Send cookies with `info.json` and image requests.                                      |
| `requestHeaders`     |          | Extra headers for those requests (these force a CORS preflight).                       |
| `media.presentation` | `"dom"`  | `"dom"` places a real `<video>`; `"texture"` draws its frames into the canvas (CORS).  |

### `CanvasHandle`

Coordinates are world units, which are the first image's own coordinates (its declared
`width`/`height`). That makes `getBounds()` an `xywh=` region as it stands.

`fitBounds(rect)`, `fitItemRect(index, rect)`, `itemRectToWorld(index, rect)`,
`getBounds()`, `getHomeBounds()`, `home()`, `zoomBy(factor, at?)`, `panBy(dx, dy)`,
`setRotation(degrees)`, `rotateBy(degrees)`, `getRotation()`, `getCamera()`,
`worldToScreenPoint(point)`, `screenToWorldPoint(point)`, and `on(event, listener)` for
`"viewport"`, `"change"`, `"error"` and `"backend"`.
