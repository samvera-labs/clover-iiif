# Viewer

<Callout type="info">
  Looking for the Viewer of Clover 3.x, `@samvera/clover-iiif`? It is at [Clover
  3.x › Viewer](/docs/3.x/viewer).
</Callout>

Clover 4.x is used two ways:

- **The Viewer**, ready-made. Give it a Manifest, and a template for a layout other than
  the default.
- **The parts** it is built from, for a layout of your own, with dot notation.

## The Viewer

`Viewer` is the package's default export.

```jsx
import Viewer from "@nulib/clover";
import "@nulib/clover/styles.css";

<Viewer iiifContent="https://iiif.io/api/cookbook/recipe/0009-book-1/manifest.json" />;
```

<ViewerDemo />

With no `template`, the Viewer draws `Default`: Clover 3.x's Viewer layout, with the
information panel beside the stage and the thumbnails under it. For another layout,
import a template and pass it:

```jsx
import Viewer from "@nulib/clover";
import { Document } from "@nulib/clover/templates";
import "@nulib/clover/styles.css";
import "@nulib/clover/templates.css";

<Viewer iiifContent={url} template={Document} />;
```

The Viewer itself is a shell of under 1 kB. It holds no layout, so a page ships only the
template it passes, and the parts that template uses: a Gallery page carries no
information panel. A template is passed, not named, for the same reason. The Viewer takes
its template's props, and TypeScript checks them: `template={Document}` brings
`defaultSidebarOpen`. See [Templates](/docs/templates) for each one.

Given no template, the Viewer loads `Default` the first time it draws, as a chunk of its
own. That costs one request before the Manifest starts to load, and the server draws
nothing for it. To have it up front and drawn on the server, pass it like any other:

```jsx
import Viewer from "@nulib/clover";
import { Default } from "@nulib/clover/templates";

<Viewer iiifContent={url} template={Default} />;
```

`Default`'s props are below. Every template also takes the [`Root` props](#root).

| Prop               | Default                     | What it does                                                    |
| ------------------ | --------------------------- | --------------------------------------------------------------- |
| `template`         | `Default`, loaded on demand | The layout: one from `@nulib/clover/templates`, or your own.    |
| `panel`            | `true`                      | The information panel and its toggle.                           |
| `defaultPanelOpen` | —                           | Whether the panel starts open. Unset: open when it fits beside. |
| `panelLayout`      | `"accordion"`               | The panel's sections as stacked boxes, or `"tabs"`.             |
| `download`         | `true`                      | A Download button, when the Manifest or page has a `rendering`. |
| `items`            | `"carousel"`                | The thumbnails: `"carousel"`, `"list"`, `"grid"`, or `false`.   |
| `filter`           | `false`                     | A filter field over the thumbnails.                             |
| `storageKey`       | `"clover-template-default"` | Where the panel's width is remembered; `false` forgets it.      |

## Your own layout

The parts are named exports. `import * as Clover` gives them dot notation, and a page
that never renders the Viewer never ships a template. Every part reads from the nearest
`Clover.Root`, so place them anywhere inside it, in any markup. Here the title, position
and buttons sit beside the stage.

```jsx
import * as Clover from "@nulib/clover";
import "@nulib/clover/styles.css";

<Clover.Root iiifContent={url} className="my-layout">
  <Clover.Content />
  <aside>
    <Clover.Label as="h3" />
    <Clover.Label of="canvas" />
    <Clover.Position />
    <Clover.Previous />
    <Clover.Next />
  </aside>
</Clover.Root>;
```

<ComposedDemo />

Every template is built only from these parts, so a template's source is a good place to
start a layout of your own: copy `Default.tsx` and `Default.css` from
`packages/clover/src/templates/default/`. `Clover.Viewer` is the Viewer again, for a page
that already imports the namespace.

## Parts

| Part               | What it renders                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| `Root`             | Loads the content and holds where the reader is. Renders a `div` (or `as`), and announces moves.       |
| `Content`          | The current view, drawn by `Canvas`: a page, a spread, a video or sound. Children join its controls.   |
| `Label`            | The Manifest's label, or the current Canvas's with `of="canvas"`, in the reader's language.            |
| `Previous`, `Next` | Buttons that move a view at a time (a spread, in a paged book), with arrows that follow the book.      |
| `Position`         | "Item 2 of 5", counted in views.                                                                       |
| `Pager`            | `Previous`, `Position` and `Next` in a `nav`.                                                          |
| `Status`           | "Loading…", or what went wrong. Nothing once loaded.                                                   |
| `Items`            | Thumbnails of the views, as a carousel, list or grid. See [Items](/docs/items).                        |
| `InformationPanel` | Tabs of information. About by default; give it `Tab`s to choose your own.                              |
| `Tab`              | One tab of the panel: `value`, `label`, and what it shows. Your own components go here.                |
| `About`            | Everything the Manifest says about itself, as 3.x's About tab shows it.                                |
| `PanelToggle`      | Shows and hides the panel. As a child of `Content`, it sits with the Canvas's controls.                |
| `Annotations`      | The view's annotations by set: content to read, a button to find each on the Canvas, a switch per set. |
| `Download`         | The `rendering` of the page in view and of the Manifest (a PDF, say), as links behind one button.      |
| `Transcript`       | The view's captions as text: the current cue marked as it plays, a press seeking there.                |
| `Contents`         | The table of contents from the Manifest's Ranges, the entry the reader is in marked.                   |
| `Search`           | IIIF Content Search (1 or 2): a field, then the hits by page with the words around them.               |
| `CollectionSelect` | In a Collection, a menu of its members; choosing one shows it.                                         |
| `Canvas`           | The renderer itself. Inside a `Root` it shows the current view; see [Canvas](/docs/canvas).            |

Parts that have nothing to show render nothing: `Pager` for a single view, `Label` with no
label.

## `Root`

| Prop                   | Type                              | Description                                                                        |
| ---------------------- | --------------------------------- | ---------------------------------------------------------------------------------- |
| `iiifContent`          | `string \| object`                | A URL, a IIIF resource (Presentation 2, 3 or 4), or a content state.               |
| `canvasId`             | `string`                          | The Canvas to show, controlled. Moving calls `onCanvasChange` instead.             |
| `defaultCanvasId`      | `string`                          | The Canvas to start on. A content state, then the Manifest's `start`, win over it. |
| `onCanvasChange`       | `(canvasId: string) => void`      | The reader moved to a Canvas.                                                      |
| `onStatusChange`       | `(status, error) => void`         | `"loading"`, `"ready"` or `"error"`.                                               |
| `request`              | `{ credentials, headers, fetch }` | Used for every request any part makes.                                             |
| `language`             | `string`                          | The language to read IIIF text in. The reader's, by default.                       |
| `annotations`          | URL, object or list               | AnnotationPages or AnnotationCollections to show beside the Manifest's own.        |
| `manifestId`           | `string`                          | In a Collection, the member to show, controlled.                                   |
| `onManifestChange`     | `(manifestId) => void`            | In a Collection, the reader moved, or asks to move, to another member.             |
| `searchQuery`          | `string`                          | A Content Search to run once the Manifest is shown, and whenever it changes.       |
| `onContentStateChange` | `({ json, encoded }) => void`     | Where the reader is, as a content state, each time it settles.                     |
| `as`                   | element type                      | Default `div`.                                                                     |

### What `iiifContent` can be

- **A Manifest.** Shown from its `start` Canvas, or its first.
- **A Collection.** Its first Manifest is shown, or the one `manifestId` names. Its
  members are listed by `Clover.CollectionSelect` (in the Viewer's header) or
  `<Clover.Items of="members">`; choosing one shows it, and a nested Collection is
  entered. Paged Collections are followed through `next`. `manifestId` with
  `onManifestChange` makes the Manifest controlled, as `canvasId` does the Canvas.
- **A Canvas.** Its `partOf` Manifest is loaded and opened at the Canvas. A Canvas with no
  `partOf` is shown on its own.
- **A content state**, as JSON or base64url. It opens at the Canvas it points to,
  framing its region (`xywh=`) or seeking to its time (`t=`), past any placeholder.
- **An object** rather than a URL, from any of these. An object is identified by its
  `id`, so a new object with the same `id` does not reload.

Everything is upgraded to IIIF Presentation 4 as it loads, so every part reads one
shape. `toPresentation4()` does the same for data you hold yourself.

### Opening at a place

A content state opens the Manifest at a Canvas, and frames a region of it. This one
points at the title on the book's title page: the second spread, zoomed in, with no
cover in the way.

```jsx
const state = {
  type: "Annotation",
  motivation: ["contentState"],
  target: {
    type: "SpecificResource",
    source: {
      id: "https://iiif.io/api/cookbook/recipe/0009-book-1/canvas/p3",
      type: "Canvas",
      partOf: [{ id: manifestUrl, type: "Manifest" }],
    },
    selector: { type: "FragmentSelector", value: "xywh=450,650,2300,1100" },
  },
};

// Encoded for a link, as the Content State API spells it.
const encoded = btoa(encodeURIComponent(JSON.stringify(state)))
  .replace(/\+/g, "-")
  .replace(/\//g, "_")
  .replace(/=+$/, "");

<Viewer iiifContent={encoded} />;
```

### Annotations and sharing

Annotations on the Manifest's Canvases (comments, tags, transcriptions) appear in an
Annotations tab and as hotspots on the Canvas. Picking one in the list frames it, moving
to its Canvas first; hovering either the entry or the hotspot highlights both. Add your
own with `annotations`:

```jsx
<Viewer iiifContent={manifestUrl} annotations={annotationPageUrl} />
```

`onContentStateChange` hands you a content state whenever the reader settles: the Canvas
and region (or moment in a video) they are at, for a link of your own:

```jsx
<Clover.Root
  iiifContent={url}
  onContentStateChange={({ encoded }) =>
    history.replaceState(null, "", `?iiif-content=${encoded}`)
  }
>
```

### Content Search

A Manifest with a IIIF Content Search service (version 1 or 2) gets a Search tab. The
hits are listed by page, each with the words around it, and drawn on the Canvas; choosing
one goes to its page and frames it. `searchQuery` searches as the Manifest opens, as 3.x's
`iiifContentSearchQuery` did:

```jsx
<Viewer iiifContent={manifestUrl} searchQuery="Vererbung" />
```

Below, the Viewer opens Clover's [Content Search mock](/docs/mocks) already searched for
"Moskau": open the Search tab to see the hits, or search again.

<ContentSearchDemo />

`Clover.Search` is the same part anywhere in a layout, and `clover.search(query)` (from
`useClover`) searches from a part of your own. The results are in the Root's state as
`search`: its `query`, `status`, `hits`, and the `set` of annotations the Canvas draws
(its id is `SEARCH_SET_ID`, so `setSetVisible` can hide the highlights).

### Video and sound

Video and sound play in the Canvas's own transport. Their WebVTT captions are drawn over
the picture and listed in a Transcript tab, from one fetch of each file; the cue playing
is marked, and pressing one seeks there. Chapters come from the Manifest's Ranges (a
Range naming the Canvas with `#t=`): notched on the seek bar, listed in a menu, and
named beside the time. A Manifest or Canvas with `auto-advance` plays the next view when
one ends, and `repeat` wraps the last to the first. Playback re-renders only what shows
the time, and changes nothing in the Root's state.

### Animations

A Canvas whose painting annotations are timed (`canvas#t=0,0.1`, one image per frame)
plays as an animation: pick "0688 Animation" or "Muybridge plate 626" above. Each frame
shows until the next starts; `auto-advance` plays it on arrival and `repeat` loops it, and
a frame bar steps, scrubs and pauses it. Every frame is loaded from the start and only
shown or hidden, so it never blinks, and nothing plays for a reader asking for reduced
motion. The animation's code loads only when one is shown.

### Renderers of your own

Give `Root` (or one `Content`) `renderers`, and a view they claim is drawn by your
component instead of the Canvas: a 3D model, a PDF, anything Clover does not draw. Claim a
view by its Canvas id, by a painted body's `format`, or with a `match` test. The first
renderer that claims a view draws it. This is 3.x's `customDisplays`.

```jsx
function ModelViewer({ bodies }) {
  // Inside the Root: Clover's hooks work here (useNavigation, useActiveCanvas, useClover…).
  return <model-viewer src={bodies[0].id} camera-controls />;
}

<Viewer
  iiifContent={url}
  renderers={[{ format: ["model/gltf-binary"], component: ModelViewer }]}
/>;
```

A renderer gets the view's `canvases`, their painting `bodies` (a `Choice` as its first
item, a `SpecificResource` as its source) and `Content`'s `children`. The Viewer and every
template pass `renderers` through to their `Root`.

| 3.x `customDisplays`         | 4.x `renderers`                                     |
| ---------------------------- | --------------------------------------------------- |
| `target.canvasId`            | `canvasId`                                          |
| `target.paintingFormat`      | `format`                                            |
| (none)                       | `match: ({ canvases, bodies }) => boolean`          |
| `display.component`          | `component`                                         |
| `display.componentProps`     | close over them: `component: (p) => <X {...p} a />` |
| `id`, `annotationBody` props | `canvases`, `bodies` props                          |
| `hooks` prop                 | Clover's hooks, called in the component             |

### Requests

`request` applies to everything: the Manifest, referenced annotation pages, `info.json`,
image tiles, captions and HLS segments.

```jsx
<Viewer
  iiifContent={url}
  request={{
    credentials: "include",
    headers: { Authorization: `Bearer ${token}` },
  }}
/>
```

A `<video>` element cannot send headers, so plain (non-HLS) video and sound get only the
credentials. So does an image served without CORS, which Clover shows as an `<img>`.

## Properties

Each IIIF descriptive property is a part of its own, reading the Manifest, or the
current Canvas with `of="canvas"`. A value passed as `value` wins, so they also work
outside a `Root`. Text is in the reader's language and marked with `lang`; HTML is
limited to what IIIF allows and sanitised, by a sanitiser that loads only when a value
carries markup.

| Part                                         | Property                                                      |
| -------------------------------------------- | ------------------------------------------------------------- |
| `Label`                                      | `label` (takes `label` rather than `value`)                   |
| `Summary`                                    | `summary`                                                     |
| `Metadata`                                   | `metadata`, as a description list; `renderValue` to customise |
| `RequiredStatement`                          | `requiredStatement`                                           |
| `Rights`                                     | `rights`, as a link                                           |
| `Homepage`, `Rendering`, `SeeAlso`, `PartOf` | Linked resources, by label, with their format                 |
| `Thumbnail`                                  | `thumbnail` (or a Canvas's first image), at `size`            |
| `Id`                                         | The resource's `id`, as a link                                |

Give the panel `onClose` and it gets a close button. Closing from inside it hands focus
back to its `PanelToggle` (whatever names it in `aria-controls`). Add `closeOnEscape` when
the panel floats over the page rather than sitting beside it.

```jsx
<Clover.InformationPanel>
  <Clover.Tab value="about" label="About">
    <Clover.About />
  </Clover.Tab>
  <Clover.Tab value="page" label="This page">
    <Clover.Label of="canvas" as="h3" />
    <Clover.Summary of="canvas" />
    <Clover.Metadata of="canvas" />
  </Clover.Tab>
</Clover.InformationPanel>
```

## Hooks

For parts of your own, inside a `Root`. Each re-renders only when what it reads changes.

| Hook                   | Returns                                                                        |
| ---------------------- | ------------------------------------------------------------------------------ |
| `useStatus()`          | `{ status, error }`                                                            |
| `useManifest()`        | The Manifest, in Presentation 4.                                               |
| `useSequence()`        | `{ canvases, views, direction }`                                               |
| `useVisibleCanvases()` | The Canvases of the current view.                                              |
| `useActiveCanvas()`    | The Canvas the reader is on.                                                   |
| `useNavigation()`      | `{ position, total, hasPrevious, hasNext, previous, next, first, last, goTo }` |
| `useLocalized(value)`  | `{ text, lang }` for a IIIF language map, in the Root's language.              |

```jsx
function PageCount() {
  const { position, total } = Clover.useNavigation();
  return (
    <span>
      {position + 1} / {total}
    </span>
  );
}
```

## Styles

Import `@nulib/clover/styles.css` once. Its rules sit in `@layer clover`, so your own
CSS wins without a fight over specificity. Without it, every part still renders a plain,
usable layout.

The stage takes its height from `--clover-content-height` (default `60vh`):

```css
.my-layout {
  --clover-content-height: 70vh;
}
```
